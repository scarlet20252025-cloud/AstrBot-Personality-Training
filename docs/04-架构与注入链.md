# 架构与注入链

改人格之前必须知道：**人格（system_prompt）在整条链路里是最弱的一环。** 有 9 个地方可能覆盖它。

---

## 一、一次对话的完整链路

```
用户消息（QQ）
  ↓
NapCat（OneBot 适配器）
  ↓
AstrBot 核心
  ├─ 读 persona（dafeiyu）→ system_prompt
  ├─ 读 chat_history/*.json → 最近 60 条上下文
  └─ 组装成 messages
       ↓
   ┌─────────────────────────────────────┐
   │ 9 个插件在这里注入（按优先级排）：   │
   │  1. owner_identity  → 追加身份说明  │
   │  2. session_context → 追加场景标记  │
   │  3. character_memory→ 注入已知角色  │
   │  4. livingmemory    → 注入长期记忆  │
   │  5. self_learning   → ⚠ 注入学到的台词 │
   │  6. group_chat_plus → 改写 system_prompt │
   │  7. sylanne         → 注入情感上下文 │
   │  8. schedule_awareness → 时间信息   │
   │  9. proactive_chat  → 主动话题标记  │
   └─────────────────────────────────────┘
       ↓
   LLM（deepseek-v4.1-flash）
       ↓
   后处理（face_convert 清理 think 块）
       ↓
   QQ 出站
```

## 二、优先级陷阱：extra_user_content_parts > system_prompt

这是最反直觉的一条。

`self_learning` 的 `llm_hook_handler` 把学到的内容注入到 **`extra_user_content_parts`**（用户消息之后），**不是** system_prompt。位置在用户消息后面，权重反而更高。

```python
# astrbot_plugin_self_learning/services/hooks/llm_hook_handler.py
CACHE_FRIENDLY_LLM_HOOK_TARGET = "extra_user_content_parts"
# 设计目的是保持 system_prompt 稳定以利 prefix cache
# 副作用：人格被压过
```

这也是为什么「改了 13 版人格都没效果」——每轮都被这层覆盖。

## 四、几个关键数据流

### 1. 人格存储

`personas` 表，`persona_id='dafeiyu'`：

```
system_prompt   TEXT   人格正文
tools           JSON   ★ None=全部工具，[]=零个工具
skills          JSON   同上
begin_dialogs   JSON   开场白
```

**读法**：必须走 API（`GET /api/v1/personas/by-id?persona_id=dafeiyu`）或 ORM。
直接读 raw sqlite 会把 JSON 列存下的文本 `'null'` 误判成字符串。

### 2. 实际上下文来源

`group_chat_plus` **不用** `platform_message_history`，它自己维护：

```
chat_history/aiocqhttp/group/538349138.json
  → list，最多 500 条
  → 每条只有 9 个字段：message_str / timestamp / sender / ...
  → ★ 纯文本载体，没有图片信息
```

所以：
- 表情包发出去后不落盘（坑 7）
- 时间戳是落库时间（坑 4）

### 3. 工具可用性

```
persona.tools
  ├─ None  → tmgr.get_full_tool_set()  全部工具
  └─ [..]  → 只有列表里的；[] 则一个都没有
```

工具清单（部分）：
- `astr_kb_search` 知识库检索
- `web_search_tavily` 联网
- `search_meme` / `send_meme` / `steal_meme` 表情包
- `remember_character` / `recall_character` 角色记忆

## 五、哪些改动需要重启

| 改动内容 | 生效方式 |
|---|---|
| 人格文本（API PUT） | 立即 |
| provider 配置（`/api/v1/providers`） | 立即 |
| 主配置（`/api/config/astrbot/update`） | 立即 |
| 插件配置文件（`config/*.json`） | **需重载插件** |
| 插件源码（`.py`） | **需重载插件** |
| 核心源码（site-packages） | **需重启 AstrBot** |

重载插件：

```bash
POST /api/plugin/reload  {"plugin_name": "astrbot_plugin_stealer"}
```

## 六、两个 API 陷阱

### 1. `POST /api/config/astrbot/update` 不保存 provider 数组

改 `provider[]` 里的字段（比如加 `reasoning_effort`），用这个端点**回读会还原**。必须用：

```
PUT /api/v1/providers/{provider_id}
```

### 2. 插件 web API 前缀是 `/api/plug/`，不是 `/api/plugin/`

```bash
# ✅ 正确
GET /api/plug/astrbot_plugin_stealer/stats

# ❌ 全部 404
/api/plugin/astrbot_plugin_stealer/...
/api/plugins/astrbot_plugin_stealer/...
```

依据：`dashboard/api/plugins.py:227` `path = f"/api/plug/{encoded_path}"`

## 七、webchat vs QQ 群：链路差异

| | webchat | QQ 群 |
|---|---|---|
| 流式 | **强制** SSE | 不流式 |
| `on_decorating_result` 钩子 | **不触发** | 正常 |
| 自动配表情包 | 测不出 | 正常 |
| think 块清理 | 无 | face_convert 补丁 |

**所以自动配表情包这类功能，只能在 QQ 群里验证。**
在 webchat 测得 0 命中，不代表功能坏了。
