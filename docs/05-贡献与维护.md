# 贡献与维护

## 改人格的流程

```
1. 复制 persona/persona-v28.md → persona-v29.md
2. 只改一处（一次改太多无法定位效果）
3. python tools/ab-persona.py <token> persona-v28.md persona-v29.md
4. 看指标：复述率 / 元话语 / MD出戏 / 自证率
5. 有改善 → 部署 → 在 persona/CHANGELOG.md 记一条
6. 没改善 → 回退，把这次的尝试也记进 CHANGELOG（失败也是信息）
```

## 三条硬规矩

**1. 人格里不许出现成品台词**

只写「遇到这种情况我怎么做」，不写「对方：X / 我：Y」。

原因：实测 8 组成品台词，**照抄率 100%**。

**2. 不许列举具体口癖词**

不写「我的口癖是呀/嘛/诶」。

原因：点名词的触发效果远大于词频。只写一次「诶」，输出里就有 41% 以它开头。

**3. 不许堆否定式规则**

不写「不要自嘲」+ 11 个 ❌ 示例。

原因：负例同样是语料。v17 有 59 处否定 + 11 组负例，效果比 v16 更差。

## 什么时候该改机制而不是改人格

看到这些症状，先查机制：

| 症状 | 查什么 |
|---|---|
| 工具全失效 | `tools` 是不是 `[]` |
| 答非所问、接不上 | 时间戳是否错序 |
| 输出通用助手腔 | 模型被换了 |
| 回复里有思考过程 | `reasoning_effort` 没关 |
| 固定句式又出现 | `expression_patterns` 又涨了 |

## 知识 vs 人格的分界

| 内容类型 | 放哪 | 原因 |
|---|---|---|
| 具体词的释义（梗、黑话） | 知识库 | 会过时，需要更新；放人格里会变台词 |
| 行为策略（怎么接话、怎么回怼） | 人格 | 是稳定的人格特质 |
| 事实（谁是谁、群规） | 记忆插件 | 会变，人格里写死会过期 |
| 攻击性黑话（典/孝/急全套） | 哪都不放 | 会让她变杠精 |

## 记 CHANGELOG 的要求

每条至少写：

- **改了什么**（具体到句子）
- **为什么改**（对应哪个实测数据）
- **实测结果**（改前 vs 改后）

没有数据的改动不算数。

## 接手须知

新会话接手时，按这个顺序读：

```
1. README.md                了解全貌
2. docs/01-踩过的坑.md      省掉几十轮试错
3. docs/04-架构与注入链.md  知道人格在链路的哪一环
4. persona/CHANGELOG.md     当前进度和方向
5. persona/persona-v28.md   当前线上内容
```

改之前先跑 `tools/diag-inject.py` 和 `tools/diag-tools.py` 确认机制层是干净的。
