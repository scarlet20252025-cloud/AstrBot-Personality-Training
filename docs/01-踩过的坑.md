# 踩过的坑

每一条都有实测证据。新会话接手前先读完这九条，能省掉几十轮往返。

---

## 坑 1：人格里写示例 = 写台词库

**现象**：不管怎么改人格，她说话都是那几个固定句子。

**证据**（2026-11-01 实测）：

把人格里 8 组「对方：X / 我：Y」的 X 当输入打回去：

```
「我昨天被坑了两百」→ 啊 两百 谁 说名字 我帮你骂      逐字重合 11/11 = 100%
「我考砸了」       → 过来 抱一下 考砸一次能说明啥…    22/22 = 100%
「我不想活了」     → 怎么了 先别急着说这个…           21/21 = 100%
「我才是奶龙」     → 奶龙 那你比我实在 我是怕胖的那个   15/15 = 100%
──────────────────────────────────────────────
A 组逐字照抄率 8/8 = 100%
```

换成「俺考砸了」「昨天我考砸了」，她**仍然输出同一句**。

**修法**：删掉所有成品台词，只留「遇到这种情况我怎么做」。

**效果**：照抄率 88% → **0%**。

## 坑 2：命名口癖是最强的重复触发器

**现象**：41% 的回复以「诶」开头。

**证据**：

v22 人格里只有一句：

> 我有几个说得顺口的词，一整天下来带个三五次就行，别每句都带。比如「呀」「嘛」「诶」。

全文「嘛」出现 1 次、「呀」2 次、「诶」1 次 —— **总共 4 个字符**。但输出里：

```
「诶」开头     41%
「嘛/呀」结尾  71%
```

**为什么**：模型对「被点名的词」远比对词频敏感。同时「三五次」是不可跟踪的数值指令，模型无法计数。

**修法**：删掉该段，改成不含具体词的结构描述。

**效果**：「诶」开头 42% → 17%（后续版本归零）。

**推论**：写「不要自嘲」并附 11 个 ❌ 示例，等于给模型 11 个坏样本。**负例也是语料。**

## 坑 3：`tools: []` 会关掉所有工具

**现象**：联网、知识库、表情包、角色记忆全部失灵。

**证据**（`astrbot/core/astr_main_agent.py:651-663`）：

```python
if (persona and persona.get("tools") is None) or not persona:
    persona_toolset = tmgr.get_full_tool_set()   # None → 全部工具
else:
    persona_toolset = ToolSet()
    if persona["tools"]:                          # [] 是 falsy → 零个工具
        for tool_name in persona["tools"]: ...
```

**根因**：我自己的部署脚本 `put-persona.py` 里硬编码了 `"tools": []`，所以**每次部署人格都会静默清空所有工具**。

**修法**：改成 `"tools": None`。

**注意**：SQLite 里 JSON 列存的是文本 `'null'`，直接读 raw sqlite 会误判成字符串。**必须通过 ORM/API 验证**（见 `tools/diag-tools.py`）。

## 坑 4：时间戳错序导致「答非所问」

**现象**：她接不上话、把说过的事当新的提。

**证据**：`platform_message_history.created_at` 是**落库时间**不是发送时间。批量写入时撞秒：

```
落库 01:50:38 这一秒挤了 9 条：
  真实 09:20:14 → id368
  真实 09:20:09 → id369   ← 比 368 早 5 秒，却排在后面
```

统计：**92 条消息里 81 条（88%）时间戳撞在同一秒**。

而 `context_manager` 拿这个时间戳排序，等于让模型看一堆「同一秒发生、先后不明」的碎片。

**修法**：两处补丁
- 从消息正文提取真实时间（`[2026-10-31 周六 09:36:05]` 就在正文里）
- 同秒消息按数据库主键二级排序

## 坑 5：中转站会偷偷换模型

**现象**：人格突然失效，输出「我默认把结论和依据分开写」「有什么可以帮」这种通用助手腔。

**证据**：某站名义上 `deepseek-v4.1-flash`，同一 prompt 下：

```
该站       → 「我默认把结论和依据分开写，方便你直接跳着看」+ **加粗** + 表格
对照片区   → 「就是个单文件的小数据库 不用装服务 直接读文件就行」
```

**修法**：`agent_runner.config.model.provider_id` 换成可靠站，并配 `fallback_provider_ids`。

**教训**：怀疑人格坏了之前，先确认模型是谁。

## 坑 6：推理模型的思考链会泄漏进正文

**现象**：回复里混进「用户说"你已急哭"——这是网络梗，调侃我急了」「Keep it one or two lines」。

**证据**：

```
baseline              4.16s  reasoning_content 66 tok
reasoning_effort=none 2.81s  无 reasoning          ← 快 1.5 倍，无泄漏
thinking=disabled     2.44s  无 reasoning
```

**修法**：provider 的 `custom_extra_body` 加 `{"reasoning_effort": "none"}`。

**注意**：必须走 `/api/v1/providers` 端点。`/api/config/astrbot/update` **不保存 provider 数组**，回读会还原成旧值。

## 坑 7：表情包发出去后她不记得

**现象**：

```
用户：用一张表情包表达你现在的心情
她：就这个 周日午后的悠闲全写在脸上了   ← 发了图
用户：这是什么意思
她：你没发图也没说前文 我猜不到你指的是啥呀   ← 隔 1 秒就忘了
```

**证据**：历史记录里那条只有纯文本，没有 image 组件：

```json
{"type":"bot","message":[{"type":"plain","text":"就这个 周日午后的悠闲全写在脸上了"}]}
```

三层原因：
1. `AstrMessageEvent.send()` 基类只记 trace，**不写** `platform_message_history`
2. 即使走核心写入，`insert_message_chain` 对 Image 也只存 `[image]` 占位
3. `group_chat_plus` 用的 `chat_history/*.json` 每条只有 `message_str` 一个纯文本字段

**修法**：给 stealer 打补丁，发图成功后往 `chat_history` 追加一条
`[我发了一张表情包：<描述>]`。

## 坑 8：webchat 测不出自动配图

**现象**：8 个情绪场景 0/8 发图，把概率调到 100% 仍然 0/4。

**证据**（日志每轮都有）：

```
[INFO] Applying streaming output (webchat).
[WARN] Plugins that depend on the pre-send event hook may not work
       correctly when streaming output is enabled.
```

插件挂在 `@filter.on_decorating_result`（pre-send），**webchat 强制流式时这个钩子不触发**。QQ 群不走流式，所以正常。

**教训**：测不出来 ≠ 功能坏了。先确认测试通道有没有走同一条链路。

## 坑 9：self_learning 会在后台学坏话

**现象**：人格改了 13 版都没效果。

**证据**：`expression_patterns` 表累积 60 条学出来的旧台词，每轮以 `<context>` 注入到**用户消息之后**（`extra_user_content_parts`），权重高于 `system_prompt`：

```
「你怎么这么人机」→「理着呢，刚在发呆。有话说呗。」
「我说你死板」    →「说谁死板呢，我那是没兴趣陪他们瞎闹」
```

清空后又会重新累积（实测一次断电重启后瞬间写回 97 条，同一秒批量落库）。

**修法**：关 `enable_expression_patterns`、`enable_auto_learning`、`enable_persona_evolution`、`auto_apply_persona_updates`，并定期清表。

## 通用排查顺序

「改了没效果」时按这个顺序查，不要先怀疑 prompt：

```
1. tools 是不是 [] ？          → tools/diag-tools.py
2. 有没有插件在注入？          → tools/diag-inject.py
3. 时间戳对不对？              → 查 chat_history 的 message_str 是否带真实时间
4. 模型是谁？                  → agent_runner.config.model.provider_id
5. 有没有学到坏台词？          → 查 expression_patterns 行数
6. 最后才改 prompt
```
